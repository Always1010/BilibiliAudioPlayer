# 缓存与本地归档规则

本文档定义缓存文件从创建、索引、展示、播放、扫描恢复到删除的完整语义。实现细节可以调整，但不得在未更新本文档的情况下改变这里描述的数据边界和安全规则。

## 设计目标

- 音频正文只保存在用户授权的本地目录中，不写入扩展存储。
- 同一个作品可以在多个栏目或播放列表中拥有彼此独立的实体副本。
- 播放时可以复用任何有效副本，但管理和删除必须精确到具体归档位置。
- 浏览器索引丢失或用户搬迁目录后，可以从磁盘文件恢复尽可能多的索引。
- 删除操作不得递归清空未知目录，也不得误删扩展没有登记的用户文件。

## 核心概念

- **作品记录（record）**：以作品 ID（通常为 BV 号）为键的逻辑缓存记录。一个作品只对应一条作品记录。
- **缓存位置（location）**：某个作品在一个具体栏目、格式和磁盘路径下的实体副本。一条作品记录可以包含多个缓存位置。
- **归档作用域（scope）**：说明缓存位置属于全部作品、合集、系列或自定义播放列表。
- **缓存索引**：IndexedDB 中保存的作品记录与缓存位置元数据，不包含音频正文。
- **归档清单**：自定义播放列表目录内的 `哔哩音频清单.json`，用于保留播放列表身份、顺序和文件映射。

“已缓存作品数”和“实体副本数”不是同一个指标。例如同一个 BV 号同时归档到全部作品、一个合集和一个播放列表时，前者计为 1，后者计为 3，占用空间按 3 个文件累加。

## 数据存放位置

### 用户授权目录

保存真实音频文件及播放列表归档清单。扩展通过 File System Access API 保存目录句柄，并在每次需要读写时检查权限。

### IndexedDB

数据库名为 `bili-audio-files`：

- `handles`：保存用户授权的缓存根目录句柄。
- `records`：以 `trackId` 为键保存缓存索引。

缓存位置至少包含：

```text
id          作用域、格式和码率组成的位置身份
scope       归档作用域的 key、type、id 和 title
path        相对缓存根目录的完整路径数组
format      original 或 mp3
bitrate     MP3 码率；原始格式为 null
mimeType    媒体类型
codec       编码信息
size        文件字节数
cachedAt    写入时间
verifiedAt  最近确认文件有效的时间
```

旧版单路径记录会在读取时自动规范为首个 `location`，不要求移动或重新下载旧文件。

### `chrome.storage.local`

保存默认缓存格式、MP3 码率、关注与追更设置、自定义播放列表等应用状态，不保存音频正文或缓存文件句柄。

### Offscreen Document 内存

缓存队列、当前任务、最近任务结果和进度只存在于离屏播放器的当前后台会话中。扩展后台会把快照和实时事件转发给界面。

## 作用域身份

缓存索引使用以下作用域键：

```text
all:<UP主UID>
season:<合集ID>
series:<系列ID>
playlist:<播放列表ID>
recovered:<相对目录路径>
```

缓存作用域键与 [`PLAYBACK.md`](PLAYBACK.md) 中的播放检查点作用域用途不同。缓存键用于定位实体归档副本；播放检查点键用于恢复集合进度，不得混用。

正常缓存写入的位置 ID 由作用域、格式和码率组成：

```text
<scope.key>:original:source
<scope.key>:mp3:<bitrate>
```

没有清单的扫描恢复位置使用包含相对路径的 `recovered:<path>` 身份；兼容读取的旧记录也可能带有路径后缀。调用方必须把位置 ID 当作不透明字符串，不得自行拆分。

队列去重和删除冲突检测使用“作品 ID + 缓存位置 ID”，因此同一作品可以进入不同栏目，也可以保留不同格式或 MP3 码率的副本。

## 磁盘目录和文件名

### UP 主归档

```text
<UP主名称>_<UID>/
├─ 全部作品/
│  └─ 001 - <作品标题> [<BV号>].m4a|webm|mp3
├─ 合集/
│  └─ <合集名称>/
│     └─ 001 - <作品标题> [<BV号>].m4a|webm|mp3
└─ 系列/
   └─ <系列名称>/
      └─ 001 - <作品标题> [<BV号>].m4a|webm|mp3
```

### 自定义播放列表归档

```text
我的播放列表/
└─ <播放列表名称> [<内部短ID>]/
   ├─ 哔哩音频清单.json
   └─ 001 - <作品标题> [<BV号>].m4a|webm|mp3
```

文件名前的三位数字是本次栏目任务中的顺序提示，不是稳定身份；恢复索引时以文件名中的 BV 号为作品身份。目录名和文件名中的 Windows 非法字符会替换为 `_`，末尾句点和空格会被移除，单个名称最长保留 100 个字符。

重命名或删除应用内的自定义播放列表不会自动移动或删除磁盘归档。播放列表元数据和实体归档具有不同生命周期，缓存文件必须从缓存管理页明确删除。

## 创建缓存

缓存命令按以下顺序处理：

```text
界面提交作品/栏目
  → Service Worker 转发 cacheTracks
  → Offscreen Document 按作品+位置去重并入队
  → 单任务串行处理
  → 写入或复用音频
  → 更新 IndexedDB 索引
  → 必要时更新播放列表归档清单
  → 广播完成、跳过或失败状态
```

具体规则：

1. 目标作用域下已经存在相同格式和码率的有效文件时，任务标记为“已经缓存”，不会重复写入。
2. 目标位置不存在，但其他作用域存在相同格式和 MP3 码率的有效副本时，直接在本地复制，不重新请求网络。
3. 没有可复用副本时，后台解析在线音频地址。
4. 原始格式按流写入 `.m4a` 或 `.webm`；MP3 会先完整下载、解码，再按设置的码率在本机转码写入。
5. 文件完整写入并关闭后才登记缓存位置。下载、解码或写入失败时中止当前写入，不创建成功索引。
6. 队列串行执行，缓存页展示当前任务、等待任务、进度和当前后台会话的最近结果。

MP3 的目标匹配必须同时满足格式和码率；原始格式没有码率维度。

## 缓存管理目录树

缓存管理页根据索引构造以下视图：

```text
UP 主
└─ 全部作品 / 合集 / 系列
   └─ 具体栏目（全部作品除外）
      └─ 实体缓存文件

我的播放列表
└─ 具体播放列表
   └─ 实体缓存文件

恢复或未分类归档
└─ 扫描得到的原目录层级
   └─ 实体缓存文件
```

每个目录节点汇总其后代的实体副本数量和字节数。UP 主节点按名称排序；UP 主内部固定按全部作品、合集、系列排序；同级目录和作品使用中文数字感知排序。目录折叠只影响渲染，不改变索引或磁盘文件。

## 本地播放命中顺序

播放作品时，播放器先根据当前队列上下文计算首选缓存作用域，然后按以下顺序尝试：

1. 与当前合集、系列、全部作品或播放列表匹配的缓存位置。
2. 其他已验证的本地位置，最近验证和最近缓存的副本优先。
3. 所有本地位置均不可用时回退在线音频。

目录没有读权限时不会把索引误判为失效。目录权限正常时，文件不存在、为空或无法解码只会移除对应位置；同一作品的其他位置会继续尝试。播放来源徽标显示最终命中的在线来源或本地归档名称。

删除正在播放的文件不会强制停止已经创建的当前媒体对象；下一次加载该作品时重新执行上述位置选择和在线回退。

## 扫描和索引恢复

“扫描归档”要求缓存根目录具有读写权限，并分两步执行：

1. 验证现有缓存位置，清除确认不存在或为空的失效位置。
2. 递归扫描授权根目录并合并识别结果。

扫描播放列表目录时优先读取 `哔哩音频清单.json`，用清单恢复作用域、作品标题、UP 主和顺序。没有有效清单时，使用目录路径推断作用域，并从下列文件名格式恢复 BV 号：

```text
[可选顺序 - ]<标题> [BV号].mp3|m4a|webm
```

扫描只合并索引，不移动、重命名或删除磁盘文件。不含 BV 号、扩展名不受支持或无法识别的文件保持原样，也不会进入索引。

## 选择和删除

### 选择语义

- 普通模式可删除单个文件或整个目录节点。
- 批量管理模式支持单个文件、栏目、UP 主、播放列表和全选。
- 选择父节点会选择所有当前可管理的后代；只选择部分后代时父节点显示半选。
- 工具栏按实体副本统计已选数量和预计释放空间。
- 正在下载或等待中的相同作品与缓存位置不可选择或删除。

### 删除语义

删除目标始终是“作品 ID + 缓存位置 ID”，不是只按 BV 号删除：

- 删除单文件只移除该路径的文件和位置索引。
- 删除合集、系列或全部作品只处理该目录树下的位置。
- 删除某个 UP 主不会删除“我的播放列表”中的相同作品副本。
- 删除播放列表归档不会删除 UP 主目录中的相同作品副本。
- 全选只包含扩展索引中登记的实体文件，不包含未知文件。

用户确认后，后台先重新检查目录读写权限，再逐个处理：

1. 删除精确文件路径，不使用递归删除。
2. 文件删除成功后移除对应位置索引。
3. 文件已经不存在时视为失效记录清理，同时移除位置索引。
4. 其他错误保留未完成项并返回失败数量，界面提示重试或扫描校准。
5. 播放列表文件删除后清空清单中的对应文件映射；清单没有剩余文件映射时删除清单。
6. 从最深层开始尝试非递归删除空目录；目录包含其他缓存或用户文件时立即停止清理。

以上规则保证删除一个位置不会破坏同一作品的其他可用副本，也不会因为删除整个逻辑分组而递归清空含有未知内容的实体目录。

## 权限和一致性边界

- 未选择目录时，缓存、扫描和删除均应提示先选择缓存目录。
- 浏览器收回目录权限后，扩展提示重新授权；重新授权前不执行写入或删除。
- IndexedDB 是播放和界面使用的快速索引，磁盘文件是真实音频来源，两者可能因用户手动操作或浏览器数据清理暂时不一致。
- 手动移动、重命名或删除文件后，应使用“扫描归档”重新校准；无法从名称或清单识别的文件需要用户自行管理。
- 删除和扫描不得越过已授权缓存根目录。
- 任何容量汇总都按索引中的实体位置计算；扫描可以用真实文件大小刷新恢复位置。

## 代码职责

- `services/cache-records.js`：缓存记录规范化、作用域、位置合并/移除、匹配和容量统计。
- `services/cache-library.js`：缓存管理目录树、实体选择键、父子选择状态和选择汇总。
- `services/file-store.js`：目录句柄、IndexedDB 索引、文件查找、精确删除和空目录清理。
- `services/archive-manifest.js`：播放列表归档清单生成、解析、恢复和删除同步。
- `services/cache-queue-state.js`：公开队列任务摘要与最近任务历史。
- `offscreen/offscreen.js`：队列执行、网络下载、本地复制、MP3 转码、扫描、删除和播放读取。
- `background/service-worker.js`：缓存命令与事件在界面和 Offscreen Document 之间的转发。
- `ui/app.js`：缓存状态展示、目录树、选择、确认和结果反馈。

## 验收场景

- 同一 BV 号缓存到全部作品、合集和播放列表后，目录树显示三个实体副本，作品数仍只计一个。
- 缓存到新栏目时，有同格式和码率的本地副本则直接复制，没有副本才联网下载。
- 当前栏目副本失效时继续尝试其他本地副本，全部失效后回退在线。
- 删除某个合集后，该合集文件和索引消失，其他栏目及播放列表副本仍可播放。
- 删除某个 UP 主后，不影响“我的播放列表”中的相同作品。
- 父节点选择、半选、全选数量和预计释放空间与实际实体副本一致。
- 删除播放列表中的单个文件后，归档清单不再指向该文件；删除全部文件后清单和空目录可被安全清理。
- 目录内存在用户自己的未知文件时，删除已登记缓存后仍保留该目录和未知文件。
- 索引存在但磁盘文件已被手动删除时，删除操作清理失效索引；扫描也能清除失效位置。
- 清理浏览器索引后扫描缓存目录，可以从播放列表清单或带 BV 号的文件名恢复可识别位置。
