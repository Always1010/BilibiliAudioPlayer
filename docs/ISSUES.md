# 问题日志

本文件用于记录项目开发过程中发现的问题、原因、处理方案和验证结果。问题对应的代码修改必须与本日志更新放在同一个 Git commit 中。

## ISSUE-001：合集与系列未能加载

- 日期：2026-09-09
- 状态：待修复
- 现象：UP 主的“全部作品”可以加载，但页面提示“部分内容暂未读取：合集与系列”，合集和系列区域没有显示。
- 原因：`background/service-worker.js` 调用 `listCreatorContainers(id, 1, 30)`，向合集接口传入了 `page_size=30`。该接口当前允许的单页数量上限为 20；传入 21 或 30 时返回 `code=-400`，请求因此失败。
- 证据：对 UID `2110052102` 的同一公开接口进行对比验证，`page_size=10` 和 `20` 返回 `code=0`，`page_size=21` 和 `30` 返回 `code=-400`。接口同时返回总数 35，说明该 UP 主确实存在合集或系列，并非空数据。
- 次要问题：后台使用 `Promise.allSettled` 保留其他成功结果，但只把失败项转换成“合集与系列”标签，没有保存和展示 `-400` 等具体错误信息，使界面无法直接说明失败原因。
- 解决方案：把单页数量限制为 20，并根据接口返回的总数继续请求后续页面，合并全部合集和系列；同时保存失败错误码和消息，在界面上显示可诊断的错误详情。
- 验证方式：修复后使用总数超过 20 的 UP 主验证至少两个分页，确认合集和系列数量完整，并验证接口异常时页面能显示具体错误码。
- 相关文件：`background/service-worker.js`、`services/bilibili.js`、`ui/app.js`

## ISSUE-002：建立问题日志与提交绑定规则

- 日期：2026-09-09
- 状态：已解决
- 修改背景：项目需要长期保留每次修改所对应的问题原因、解决方案和验证结果，并与代码提交一一关联。
- 原因：原有 `AGENTS.md` 只规定每次修改必须本地提交，没有规定维护独立的问题追踪文档。
- 解决方案：新增本文件，并在 `AGENTS.md` 中规定每次项目修改都要同步更新问题日志，且代码与日志必须进入同一个 commit。
- 验证方式：确认 `AGENTS.md` 包含问题日志规则，且 `docs/ISSUES.md` 已记录当前已定位的问题。
- 相关文件：`AGENTS.md`、`docs/ISSUES.md`
