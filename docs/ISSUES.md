# 问题日志

本文件用于记录项目开发过程中发现的问题、原因、处理方案和验证结果。问题对应的代码修改必须与本日志更新放在同一个 Git commit 中。

## ISSUE-001：合集与系列未能加载

- 日期：2026-09-09
- 状态：已解决
- 现象：UP 主的“全部作品”可以加载，但页面提示“部分内容暂未读取：合集与系列”，合集和系列区域没有显示。
- 原因：`background/service-worker.js` 调用 `listCreatorContainers(id, 1, 30)`，向合集接口传入了 `page_size=30`。该接口当前允许的单页数量上限为 20；传入 21 或 30 时返回 `code=-400`，请求因此失败。
- 证据：对 UID `2110052102` 的同一公开接口进行对比验证，`page_size=10` 和 `20` 返回 `code=0`，`page_size=21` 和 `30` 返回 `code=-400`。接口同时返回总数 35，说明该 UP 主确实存在合集或系列，并非空数据。
- 次要问题：后台使用 `Promise.allSettled` 保留其他成功结果，但只把失败项转换成“合集与系列”标签，没有保存和展示 `-400` 等具体错误信息，使界面无法直接说明失败原因。
- 解决方案：`listCreatorContainers` 现在会把 `page_size` 强制限制在 1–20；新增 `listAllCreatorContainers`，根据接口返回的总数依次读取全部分页，并按 ID 去重合并合集和系列。后台改用完整分页函数，并把失败项的错误码和消息写入警告文本。
- 验证方式：新增自动化测试模拟两页、三条数据，确认超限的 30 会被收敛为 20，且两页中的合集和系列都被完整合并。随后对所有 JavaScript 模块执行语法检查，并重新验证 UID `2110052102` 的公开接口：两页均返回 `code=0`、总数 35；第 1 页返回 20 个合集，第 2 页返回 14 个合集和 1 个系列。
- 相关文件：`background/service-worker.js`、`services/bilibili.js`、`ui/app.js`

## ISSUE-002：建立问题日志与提交绑定规则

- 日期：2026-09-09
- 状态：已解决
- 修改背景：项目需要长期保留每次修改所对应的问题原因、解决方案和验证结果，并与代码提交一一关联。
- 原因：原有 `AGENTS.md` 只规定每次修改必须本地提交，没有规定维护独立的问题追踪文档。
- 解决方案：新增本文件，并在 `AGENTS.md` 中规定每次项目修改都要同步更新问题日志，且代码与日志必须进入同一个 commit。
- 验证方式：确认 `AGENTS.md` 包含问题日志规则，且 `docs/ISSUES.md` 已记录当前已定位的问题。
- 相关文件：`AGENTS.md`、`docs/ISSUES.md`

## ISSUE-003：多个独立修改需要拆分提交

- 日期：2026-09-09
- 状态：已解决
- 修改背景：一次请求可能同时包含多个相互独立的问题或功能，需要让提交历史能够分别追踪和回退每项修改。
- 原因：原有规则只要求“一个提交只包含同一目的的相关修改”，没有明确要求一次请求中的多个独立事项必须分步提交。
- 解决方案：在 `AGENTS.md` 中明确规定按问题或功能拆分小型 commit，并要求每个提交各自包含对应代码、测试和问题日志。
- 验证方式：确认 Git 提交规则明确包含“多个独立事项不得合并为一个大提交”的要求。
- 相关文件：`AGENTS.md`、`docs/ISSUES.md`

## ISSUE-004：UP 主主页未展示合集和系列封面

- 日期：2026-09-09
- 状态：已解决
- 现象：合集或系列进入详情页后可以看到封面，但 UP 主主页的栏目列表只展示标题和作品数量，没有封面。
- 原因：接口适配层已经把 `meta.cover` 保存为栏目对象的 `cover` 字段，详情页也正常使用；UP 主主页的 `sectionCard` 模板遗漏了封面元素，导致数据存在但没有被渲染。
- 解决方案：在有封面的栏目卡片中加入可点击的 16:10 缩略图，并分别调整完整页面、侧边栏和窄屏布局；点击封面与点击标题一样进入栏目详情。
- 验证方式：执行全部 JavaScript 语法检查和 `git diff --check`，确认栏目模板使用 `section.cover`，且不同宽度下的网格列与操作区位置均有对应样式。
- 相关文件：`ui/app.js`、`ui/app.css`、`docs/ISSUES.md`
